# AI 路由评估台账

目的：在不增加运行时依赖的前提下，记录 Terra / Sol 的实际路由效果。连续完成 10 个、20 个任务后，基于返工和验证结果调整路由阈值，而不是凭单次印象调整。

## 使用规则

- 每个完成的开发、诊断或审查任务写一行；不记录密钥、用户资料或完整日志。
- `主路由` 是完成主要工作的模型；只有实际发生时才填写 `Sol 介入`。
- `是否返工` 仅记录由模型遗漏或错误导致的额外修复；正常需求变更不计入返工。
- 验证写实际运行的最小命令或检查结果；未运行时写“未运行（原因）”。
- 高风险任务（支付、权限、迁移、并发、公共接口）即使 Terra 首轮完成，也应保留 Sol 规划或只读审查。

## 路由阈值

| 条件 | 默认路由 | Sol 介入条件 |
|---|---|---|
| 单模块、需求明确、可逆且有现成测试 | Terra | Terra 无法确认调用链、测试失败或出现产品策略缺口 |
| 两个以上子系统、兼容性不确定 | Terra 首轮 | Sol 规划或审查一次 |
| 支付、认证/授权、数据库迁移、并发、数据恢复、公开接口 | Sol 规划 → Terra 实现 | 实现后 Sol 只读审查一次 |

## 第 10 / 20 个任务复盘

在第 10、20 行填写后，由任务负责人完成一次简短复盘：

| 指标 | 计算方式 | 第 10 个任务 | 第 20 个任务 |
|---|---|---|---|
| Terra 首轮无需返工率 | Terra 主路由且“是否返工=否” ÷ Terra 主路由任务数 |  |  |
| Terra 升级率 | 有 Sol 介入的 Terra 主路由任务 ÷ Terra 主路由任务数 |  |  |
| 高风险 Sol 覆盖率 | 有 Sol 规划或审查的高风险任务 ÷ 高风险任务数 |  |  |
| 验证完成率 | 有通过的实际验证记录 ÷ 全部任务数 |  |  |

调整规则：

- Terra 首轮无需返工率低于 80%，或验证完成率低于 90%：收紧 Terra 范围，将“两个以上子系统”全部提前交 Sol 规划。
- 高风险 Sol 覆盖率低于 100%：立即恢复“所有高风险任务必须 Sol 介入”。
- 连续两次复盘中 Terra 首轮无需返工率至少 90%、验证完成率至少 95%，且无高风险漏审：可把具有现成测试的双模块非高风险任务保留为 Terra 首轮 + 按需 Sol 升级。
- 平台未提供精确 token / 成本指标时，不估算节省比例；只记录路由次数、返工与验证质量。若平台后续提供指标，再在本表增加实际输入/输出 token 与成本列。
